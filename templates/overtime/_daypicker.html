{# Multi-day time picker — shared by New Request and New Actual =========================================================== A calendar to pick the days, and a block per day holding up to two time ranges, because the common pattern is a stint before the shift and another after it. Every filled range becomes its own overtime record. Context it expects: holidays — list of ISO dates that pay double (from the route) prefill — {"days": [{"date","s1","e1","b1","l1","s2","e2","b2","l2"}, …]} dp_lunch — show the unpaid lunch row (actuals only, see below) dp_verb — button wording, "{n}" replaced by the entry count dp_form_id — the form to guard against submitting with no days picked dp_index — optional. Set this when more than one picker sits on the same page (e.g. one per personnel member on New Request) so every element id and every field name is namespaced to that picker — "dates_2", "s1_2_2026-08-05" — instead of colliding with the others. Left unset, ids and field names are exactly what they always were ("dates", "s1_2026-08-05", …), so a page with a single picker (New Actual, and previously New Request) needs no changes at all. Deductions — an unpaid lunch, and minutes lost to clocking in late or leaving early — are captured on the actual and never on the request. Whoever raises a request has no way of knowing whether a break will be taken or how long it is; that differs by division and by shift. So a request is the clock-on to clock-off window, and only the actual carries the deductions. They are entered as plain minutes rather than as times, because that is how a supervisor knows them: nobody records the clock time a break started. Style and script sit here with the markup rather than in the page's head and foot blocks, so a screen picks the whole component up with one include. #} {% set idsuf = ('-' ~ dp_index) if (dp_index is defined and dp_index is not none) else '' %} {# A page with several pickers (New Request) passes its per-section prefill as dp_prefill rather than overwriting the page-level `prefill` — reassigning that inside a loop is easy to get subtly wrong across Jinja versions, so it's avoided rather than relied on. A single-picker page keeps using `prefill` exactly as before. #} {% set _dp_pf = dp_prefill if (dp_prefill is defined and dp_prefill is not none) else prefill %} {% if dp_index is not defined or dp_index is none or dp_index == 0 %} {% endif %}
